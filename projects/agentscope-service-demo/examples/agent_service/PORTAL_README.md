# 学习版用户与资源管理

## 使用

按原有方式运行 `python main.py` 和 `examples/web_ui` 下的 `pnpm dev`。
前端 `/api/service` 通过 Node 转发到虚拟机 `127.0.0.1:8000`，无需用户填写服务器地址。

- 管理员：用户名 `wei`（可以通过启动 Python 时设置 `PORTAL_ADMIN` 更换）。
- 管理入口：浏览器原来的转发地址加 `/admin`。
- 用户入口：同一地址加 `/chat`。
- 切换身份：`/setup`。

1. 管理员在“智能体”中创建或编辑智能体，表单沿用原项目。
2. 在“资源中心”进入原 MCP、技能、知识库、模型凭据页面配置真实资源。
3. 在“用户管理”创建用户名，填写邮箱和角色。用户名使用英文字母、数字、`_.@+-`。
4. 在“访问授权”选择用户或角色、智能体，并勾选 MCP、技能、知识库、模型凭据。
5. 用户在 `/setup` 输入已开通的用户名。进入 `/chat` 后只看到已授权智能体。
6. 用户创建会话，勾选 MCP、技能、知识库并点击“应用选择”，选择获准的模型后聊天。

角色授权与用户授权按并集合并。想撤销某个能力，需要从所有匹配授权中取消。
角色在编辑用户时创建；管理员只有初始的 `PORTAL_ADMIN` 身份。

## 实现位置

- `portal.py`：管理 API、持久化授权、只读资源共享策略、请求校验、运行时工作区。
- `main.py`：接入 `PortalPolicy`、`PortalWorkspaceManager`、`install_portal`。
- `../web_ui/frontend/src/pages/admin/index.tsx`：管理页。
- `../web_ui/frontend/src/components/chat/CapabilityPicker.tsx`：用户能力选择。
- `../web_ui/backend/src/index.ts`：支持流式响应的同源代理。
- `../../src/agentscope/app/_service/_toolkit.py`：工具装配时执行可选工作区授权过滤。

`portal-data.json` 保存用户、角色、授权与会话选择，不提交 Git。Agent、凭据、MCP、技能和知识库仍使用原存储。
该 JSON 存储用于当前单进程学习环境；多进程部署应替换为数据库事务。

## 行为边界

当前沿用用户名识别，未实现密码或 Key 校验。前端显示与 Python API 都校验授权，但输入管理员用户名即可成为管理员，适用于本地学习环境。

管理员资源归属初始管理员账号。新建普通用户以只读方式使用这些资源，各自的会话及工作目录独立。
MCP 配置在服务端加载，普通用户只能选择被授权的 MCP。技能使用已安装库中保存的 `SKILL.md` 指令内容，
供 Agent 的 Skill 工具加载；不会自动授予技能附件脚本所需的 Shell 或任意文件操作权限。
当前普通用户工具集合包含已选 MCP、Skill 和知识库检索；主机文件工具、定时任务及团队创建工具不开放。

授权变更后已有上下文可能含旧资源信息，因此旧会话再次发消息时会要求新建会话。
选择不同能力不会抹除已经出现的历史消息；如需干净上下文，请新建会话。
MCP/技能的启用状态在运行时检查，停用用户会立即被后续请求拒绝。

知识库沿用示例的内存 Qdrant，重启 Python 后需重新索引文档；如需长期保存索引，应另行配置持久化向量存储。

## 验证

在本目录、已激活项目虚拟环境时执行：

```bash
python -m unittest test_portal -v
python portal_smoke.py
```

冒烟检查通过实际服务的同源代理，临时创建用户、智能体、模型凭据和知识库，验证权限和跨用户隔离。
完整 Agent 回复使用仅监听本机的模拟模型，不调用付费服务；测试结束清理它创建的记录。
测试必须在服务完成启动后执行，不要同时编辑 Python 文件触发重载。
