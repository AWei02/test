# 项目文件（学习环境第一版）

## 使用

在聊天侧栏“项目”标题旁点击 ＋ 创建项目，选择已授权智能体；默认关闭共享。项目行可展开自己的会话，创建者的右侧“⋯”提供“编辑项目 / 删除项目”，写字图标直接新建项目会话。点击项目名称或聊天顶部“项目文件”进入文件管理页。旧项目未记录智能体时，新建会话优先使用当前已授权智能体，再使用已有项目会话的可用智能体或第一个可用智能体。

删除项目必须在二次确认框选择“确认删除”，接口也要求 `confirmed: true`。删除为逻辑删除：设置 `deleted: true` 并关闭共享，项目对所有用户隐藏，文件路径访问被拒绝，原始文件、备份和会话绑定保留。暂不提供界面恢复；管理员可在备份后人工恢复该项目的 `deleted` 字段，重新共享需明确开启。

“我的”列出自己创建的项目；“共享”列出当前可访问的所有共享项目（包括自己共享的项目）。项目创建者可在设置中开启共享。有项目指定智能体权限的用户可读写同一文件目录，但会话列表、聊天记录、模型和工具选择仍各自独立；共享并不会授予新的 MCP/技能权限。关闭共享或撤销智能体授权后，其他用户后续文件操作会被拒绝，既有聊天记录保留。

例如：“列出当前项目文件，读取 input.txt，整理后写入 report.txt”。CSV、PDF 等复杂处理需要选择并应用对应的已授权技能；技能脚本中的输入和输出路径使用 `/work/文件名`。项目不会自动授予 MCP 或技能，也不会自动把所有文件全文塞入模型上下文。

选择“普通对话”不需要项目，文件仍按用户、智能体、会话隔离。已有会话和文件不自动迁移。知识库功能没有改动。

## 文件与隔离

会话行的“⋯”支持重命名、置顶/取消置顶、删除。项目会话在各自项目内置顶；普通会话的置顶项排在普通列表最前。置顶信息持久化到 `portal-data.json` 的 `session_pins`，按用户名和智能体/会话 ID 隔离。删除会话需二次确认，仅删除自己的会话及聊天记录，不删除项目共享文件。

- 项目归创建用户所有；仅创建者能修改项目信息和共享设置。私有项目其他用户不可访问；共享项目仅向指定智能体的授权用户开放文件，任何情况下不共享其他人的会话。
- 文件列表、上传、下载、改名、删除及历史文件恢复在项目页完成。
- 项目智能体一旦指定即固定，避免改变共享权限范围；新建项目会话使用侧栏图标，项目详情不再重复提供新建入口。
- 项目详情可删除自己的会话；页面中的文件、历史版本和会话删除均需二次确认。当前文件删除保留备份，历史版本仅项目创建者可彻底删除，且只影响选中的版本文件，不影响当前文件和其他备份。
- 当前只管理根目录平铺文件，单文件上传/下载最大 20MB；请让脚本将结果保存到 `/work` 根目录。
- ProjectFiles 工具可列出、读取 UTF-8 文本、写入文本、改名和删除当前文件区的文件。二进制处理由已授权技能完成。
- 修改前保存根目录文件备份；一次快照上限 250 个文件、100MB，超过上限或存在超大文件需管理员整理。子目录不在这一版的文件管理/备份范围内。
- 同一文件区的项目文件操作和 RunSkill 执行由锁串行化，并非多用户协同编辑或内容自动合并。
- Docker 技能运行继续使用原有隔离限制，项目共享目录作为 `/work` 挂载。不能使用其他项目目录。

## 实现位置与验证

### 所有权转移

- 项目详情提供“转移所有权”，仅原所有者或管理员可操作，需二次确认。
- 新所有者须为启用用户且具有项目智能体权限（管理员除外）；提交时重新验证身份、目标权限和原所有者版本。
- 仅更新 owner，项目 ID、文件、历史、频道绑定和共享设置不变；会话仍归原用户。原所有者失去管理权，后续访问按共享和授权判断。
- 管理后台智能体卡片提供删除及二次确认。删除接口检查用户、角色的访问授权引用，返回阻塞授权编码；与授权写入串行处理。删除使用框架原有级联行为，会清理关联会话，应谨慎操作。
- `python test_transfer_delete.py` 使用临时数据验证转移、隔离和授权引用阻塞，不调用模型。

### 项目频道

- 创建频道时选择已有项目，路由使用该项目的智能体；已绑定项目不可切换，避免旧会话串用项目上下文。
- MCP、技能和知识库默认全选；频道卡片的“频道能力”可保存一个独立选择，空列表表示全部取消。下次调用加载新选择，不清除历史消息，也不影响其他频道。
- 频道会话绑定同一项目文件目录，ProjectFiles 和 RunSkill 沿用项目文件锁与备份；对外频道不加载管理员的通用主机、任务或团队工具。
- 旧频道保持原配置，可编辑补绑项目。项目被删除或路由智能体不匹配时拒绝运行，不退回管理员工作区。
- 离线测试：`python -m unittest test_channel_projects test_portal`；禁用频道接口测试：`python test_channel_projects_live.py`。均不调用付费模型，后者不会连接外部平台。

- `project_files.py`：项目、会话归属、文件管理接口、ProjectFiles 工具。
- `skill_packages.py`：根据会话归属选择项目目录或原独立目录，技能运行前备份并加锁。
- `portal.py`：路由注册、普通用户工具授权过滤。
- `examples/web_ui/frontend/src/pages/projects/`、`ProjectFileManager.tsx`：项目与文件页面。

从 `examples/agent_service` 运行 `../../.venv/bin/python test_projects.py`，测试会创建并删除专属测试记录，不调用付费模型；覆盖跨会话共享、真实 Docker 脚本输出、用户/项目隔离、普通对话隔离及恢复。

`../../.venv/bin/python test_shared_projects.py` 另覆盖默认私有、共享发现和写入、会话保密、共享撤销、授权撤销、重新授权及错误智能体拒绝。

部署仍是单进程学习环境，沿用用户名登录。项目元信息在 `portal-data.json`，文件和历史在 `project-data/`，两者都需要持久化备份。历史版本暂不自动清理，长期使用需关注磁盘空间；生产化前需完善真实认证、配额和多进程存储/锁。
