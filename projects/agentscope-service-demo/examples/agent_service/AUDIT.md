# 执行审计

本部署使用 AgentScope 的 `TracingMiddleware` 采集执行明细，写入本地 SQLite；不安装 Langfuse，不向外部追踪服务发送数据。

## 使用

- 项目详情的「审计记录」：查看时间、所属账号、问题、回答、状态、耗时、Token 与工具次数；支持来源和状态筛选、分页。
- 点击记录：右侧展开模型输入输出、工具参数结果、异常及触发信息。
- 聊天回复下的「执行详情」：查询对应回复，人工确认后的继续执行按同一 `reply_id` 关联。
- 管理员可展开「历史渠道会话」，查看接入前已经保存的渠道消息。旧消息不会补造模型追踪数据。

普通成员只可查看自己的执行，项目访问权限被撤销后不能读取该项目记录；项目拥有者不会因此获得其他成员的私人执行数据。管理员可查看项目内所有记录。鉴权沿用平台现有用户身份机制。

## 存储与边界

- 路径：`/workspace/data/agentscope/audit/executions.sqlite3`，随 `AGENTSCOPE_DATA_DIR` 调整。
- 记录保留 30 天，写入时清理过期记录。SQLite 使用 WAL；备份应使用 SQLite backup API 或停服务后复制数据库及相关文件。
- 一条记录对应一次 `ChatService.run`；一次运行中多次模型调用的 Token 相加，未返回用量显示 `—`。
- 单段内容最多 20,000 字符、集合最多 100 项、执行明细最多 500 个 span。截断会显示标记。
- 常见密码、API key、Authorization 等字段会隐藏。自由文本中的所有个人信息不属于自动脱敏的保证范围。
- 工具的结构化错误/拒绝会显示异常；工具返回普通文字“失败”不能可靠地自动判断业务结果。
- 会话来源表示会话类型，入站触发信息可进一步标记渠道、定时任务；渠道所属账号与本次消息发送者分别记录，后台触发没有实际发送人时不推测。
- 自定义 RAG 内部阶段、文档入库、账号权限变更尚无独立追踪。
- 当前运行先保存基础记录，完成后保存详情。进程被强制终止可能留下执行中的基础记录，不能视为仍在运行的可靠信号。
- 这是排查执行过程的本地记录，不是防篡改日志。删除会话不立即删除其项目审计记录，记录按保留期清理。

## 实现

`execution_audit.py` 管理本地 span 采集、SQLite 和受权限保护的 API；`main.py` 初始化并在原有中间件工厂中附加追踪。框架的 lifespan 将可选 observer 交给 ChatService，ChatService 在运行、准备失败和回复失败处调用 observer；未配置 observer 的其他应用保持原行为。

API：

- `GET /portal/projects/{pid}/audit`
- `GET /portal/audit/runs/{run_id}`
- `GET /portal/audit/sessions/{agent_id}/{session_id}/replies/{reply_id}`

## 全站汇总

管理员打开「管理后台 → 全站审计」（也可访问 `/admin?tab=audit`），查看所有用户的项目和普通会话记录。支持用户、项目（含仅未关联项目）、来源、状态及最近 24 小时/7 天/30 天筛选。记录保留期内，即使原项目或会话已删除，管理员仍可从全站列表查看详情；普通用户没有全站查询权限。

新增 API：`GET /portal/audit/runs` 和 `GET /portal/audit/options`，均仅管理员可访问。

## CSV 导出

- 执行详情 → 导出会话 CSV：导出该会话当前完整的用户/AI消息历史（不限审计保留期），一行一轮问答，连续用户消息以换行合并；未回复的问题保留空回答。
- 全站审计 → 下载 CSV：导出当前用户、项目、来源、状态、最近 1/7/30 天筛选下的问题及对应回复，不受列表分页影响；人工确认的同一回复去重。
- 字段：执行时间（北京）、用户、来源、项目名称、会话名称、会话 ID、用户问题、AI 回答、模型名称、输入 Token、输出 Token、执行状态、错误信息。历史消息无审计元数据时，相应字段留空。
- 输出为 UTF-8 BOM CSV，保留正文换行和标点；不导出系统提示词、思考内容和工具原始数据，公式样式文本加前导单引号避免 Excel 执行。
- 会话已删除时无法下载完整会话，接口返回明确错误；全站导出仍可使用保留的审计文本，此时可能含既有截断标记。导出反映读取时已保存的消息，执行中的最终回复请结束后重新导出。
