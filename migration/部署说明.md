# AgentScope 全新 Ubuntu 部署

此包保留当前代码、服务环境配置和站点 Logo，不包含旧数据库、用户、模型凭证、智能体、技能、项目、会话、附件、审计记录或记忆。原服务器没有被清空。
代码不包含 .git、.venv、node_modules 和构建缓存。配置包含真实密码及 MINERU_API_TOKEN，请妥善保存。

## 1. 准备运行环境
推荐 x86_64 Ubuntu，安装 Python 3.12（含 venv）、Node.js 24、pnpm 12.4.1、Docker Engine 和 Docker Compose 插件、unzip、git、构建工具。需要联网下载 Python/Node 依赖和 Docker 镜像。这不是离线镜像包。
原机版本：Python 3.12.14 / Node v24.21.0 / pnpm 12.4.1 / Docker 29.7.2 / Compose v5.5.0。
当前用户必须能够执行 docker（加入 docker 组后重新登录）。以下应用命令使用普通部署用户执行，不要 sudo pip 或 sudo pnpm。

## 2. 解压到原目录结构
将两个 ZIP 放在同一个目录，在该目录执行：
```bash
sudo mkdir -p /workspace/projects /workspace/data/agentscope
sudo chown "$(id -u):$(id -g)" /workspace/projects /workspace/data/agentscope
unzip agentscope-code.zip -d /workspace/projects
unzip agentscope-config.zip -d /workspace
chmod 600 /workspace/projects/agentscope-service-demo/examples/agent_service/.env
```
仅适用于全新服务器；已有同名项目或数据目录时不要直接覆盖。
配置包解压后会生成 projects/.../.env、data/agentscope/portal/portal-data.json 和 migration/ 部署资料。

## 3. 检查配置
检查 examples/agent_service/.env 中的 MinIO、Neo4j 配置。当前 Python 与数据库都部署在同一台主机，localhost 地址可以沿用。
不要运行 reset_platform_data.py、migrate_storage.py、migrate_blobs_to_minio.py；这些是历史维护工具，全新部署不需要。
保持默认数据路径 /workspace/data/agentscope。若要更换路径，需统一检查 Python 启动环境和 Compose 配置，不要仅修改 .env 的路径。

## 4. 安装后端依赖
```bash
cd /workspace/projects/agentscope-service-demo
python3.12 -m venv .venv
.venv/bin/python -m pip install --upgrade pip
.venv/bin/python -m pip install -c /workspace/migration/python-constraints.txt -e '.[service,storage-redis,storage-s3,channel,rag,vdb-qdrant,tools]' neo4j python-multipart PyYAML -r examples/agent_service/requirements-parsing.txt
.venv/bin/python -m pip check
```
constraints 文件记录原机已安装包版本；只限制本次需要安装的依赖，不会安装其中所有开发测试包。不同 CPU 架构或 Python 版本未验证，请优先使用相同架构和 Python 3.12。

## 5. 启动存储和后端
```bash
cd /workspace/projects/agentscope-service-demo/examples/agent_service
docker compose --env-file .env -f compose.storage.yaml up -d
docker compose --env-file .env -f compose.storage.yaml ps -a
```
等存储服务就绪，minio-init 应成功退出（Exit 0），再执行：
```bash
../../.venv/bin/python main.py
```
另一个终端检查：
```bash
curl -f -H 'x-user-id: wei' http://127.0.0.1:8000/health
```

## 6. 安装并启动前端
新开终端：
```bash
cd /workspace/projects/agentscope-service-demo/examples/web_ui
HUSKY=0 pnpm install --frozen-lockfile
pnpm dev
```
浏览器打开 http://新服务器IP:5173，以 wei 进入平台。此用户名是平台默认管理员，与 Ubuntu 用户名无关。前端通过本机 3000 端口代理到 Python 8000 端口。
当前启动方式沿用开发启动方式；关闭终端会停止应用。若需要长期运行，另行配置 systemd 或进程托管。
只向可信网络开放应用入口，不要把数据库端口改为公网绑定。

## 7. 重新配置业务资源
重新添加模型凭证、智能体、用户授权、技能、知识库等。旧技能包和 Docker 技能镜像未迁移，上传技能后重新构建。
此前本地模型地址 http://192.168.0.218:8000/v1，模型名 deepseek-v4-flash-vision；该模型服务不在此迁移包中，新服务器必须能访问它。添加模型后按需开启视觉。
MinerU 推理服务等外部服务也未打包，使用前检查地址及 Token。
